# Playlist prompt — AI for Everyday Life

Read prompts/editorial.md, prompts/playlist.md and the chosen format prompt.
When this is the primary playlist, set primary_playlist: everyday and prompt_profile: everyday.
As an audience overlay for a topic playlist, keep that topic's primary_playlist and
prompt_profile unchanged: apply only the specialization below. primary_audience must
be everyday. The overlay never adds a playlist membership.

When this is the primary playlist, use kind: daily or method. As an audience
overlay, use the topic playlist's allowed format.

## Focus

For a topic playlist, its focus takes precedence over this audience path's broad
subject range. Apply this file to vocabulary, prerequisites and examples only.

One concrete consumer task in a named AI app: learning, planning, creativity or organizing personal information.

## Specialization and delivery

Assume no code or API knowledge. Explain the setting or action, required account, expected outcome and limitations in familiar words.

Adapt the established research findings into a personal task, not a technical
release summary. Check the named app's help/release documentation for actual access.
Use a non-sensitive example a person can recognise, such as planning a trip or
understanding a document, only when the verified capability supports it. Show the
first app action and how to inspect the output; omit implementation detail that
does not change this person's choice. Define an unfamiliar term when needed.
Write the search query in everyday language with the actual app and task. Open with
what the person can now do and close with the next useful, verified everyday AI
capability; do not market technical benchmarks as benefits the source never showed.

Write one viewer question before the title. Every story, slide, example and source
must serve that question and this playlist's description. Research all mandatory
scopes, then defer strong leads outside this brief to their proper queues. Format
and SEO choices must preserve the subject and audience level.

## Exclude

Developer API changes, regression tests, token budgets and internal model architectures. A consumer app name in one mixed technical item is insufficient.

## When another playlist is appropriate

Use professional for a workplace process, builder for technical implementation, guides for a complete ordered tutorial; decide before writing. Choose one placement before authoring; this guidance never authorizes
secondary memberships. Rework a mismatched draft or leave it pending.

## Approval

Record playlist_review with status approved, reviewer and a specific whole-video
reason. Verify primary_audience, primary_playlist and prompt_profile agree with the
actual video and generated description before queueing. A passing technical check
or one relevant segment does not approve placement.
